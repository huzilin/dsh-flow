## 1. 问题陈述（为什么做）

### 1.1 现状与证据

平台没有外层的需求/版本管理入口，无法呈现需求池全景、筛选、管理需求归属与版本推进。

### 1.2 影响与代价

缺乏看板 → 无法直观掌握需求状态与优先级；缺乏需求管理 → 无法建立需求字段审计留痕；缺乏版本管理 → 无法推进版本、联动需求状态。

### 1.3 时机与约束

模块 I 与模块 II 构成工作台「外层看板 → 内层流程树」两级结构，需在平台 MVP 落地。

## 2. 目标与成功指标

### 2.1 业务结果指标

| 指标 | 当前基线 | 目标值 | 观察周期 | 数据口径 |
|---|---|---|---|---|
| 需求可管理性 | 无 | 支持新建/编辑/删除/审计 | — | 需求 CRUD 全链路可用 |
| 版本可推进性 | 无 | 版本状态机单向推进 | — | 待启动→进行中→已发布 |

### 2.2 交付结果指标（护栏 Guardrails）

| 指标 | 底线要求 |

| 删除/废弃安全性 | 二次确认；删需求不删磁盘目录；废弃联动需求已取消 |

## 4. 用户与场景

### 4.1 用户角色

| 角色 | 特征 | 目标 |
|---|---|---|
| User | 项目负责人 | 查看全部需求、管理需求与版本、进入流程树 |
| Leader | 主 agent | 通过 `wb_*` 工具管理需求/版本（与 UI 共用领域逻辑） |

### 4.2 主路径

进入 `conversation.view`（id=`workbench`）tab → 默认看全部需求（版本「全部」× 优先级「全部」）→ 顶部「看板/列表」切换 → 顶栏「＋新建需求」创建 → 卡片/行点击进入流程树（模块 II）→ 版本管理弹窗推进/废弃版本。

### 4.3 高频异常场景

- 新建需求标题为空 → 保存禁用 + 红框提示。
- 删除需求/废弃版本 → 二次确认弹窗；废弃联动需求已取消。
- 删除有需求引用的版本 → 禁止（提示引用数，先移出）。
- 无流程数据需求进详情 → 显示「暂无流程数据」+ 返回，不卡 loading。

## 5. 功能需求

### 5.1 功能总览

| 功能模块 | 优先级 | 描述 | 状态 |
|---|---|---|---|
| 版本看板 | P0 | 状态四泳道 + 需求卡（优先级徽标） | 待开发 |
| 需求池 | P0 | 看板/列表双视图、版本×优先级筛选 | 待开发 |
| 需求管理 | P0 | 新建/编辑/删除 + Markdown 描述 + 变更历史 | 待开发 |
| 版本管理 | P0 | 版本 CRUD + 状态机 + 进度汇总 | 待开发 |

### 5.2 功能详细说明

#### 版本看板（默认视图）

**功能描述**：进入 tab 默认看全部需求；列 = 状态四泳道（待启动/进行中/已完成/已取消）。

**用户故事**：作为 User，我希望按状态泳道查看全部需求卡，以便一眼掌握需求分布。

**交互流程**：进入 tab → 看板视图 → 顶部「看板/列表」切换 → 版本×优先级筛选（取交集）。
1. 列头 = 状态色圆点 + 状态名 + 该列条数；空列显示空容器。
2. 需求卡要素：标题 + 类别徽标 + 优先级徽标 + 版本名 + 负责人。
3. 优先级徽标颜色：P0 红 / P1 橙 / P2 蓝 / P3 灰。
4. 筛选：两维度取交集，看板与列表共用同一过滤结果；「全部」为前端虚拟选项（`__all__`）不入库。
5. 卡片点击 → 进入流程树（模块 II）。

**业务规则**：
- 优先级颜色映射（纯展示约定），缺省渲染 `—`。
- 版本名自由文本：id 稳定短码 `v-<n>`；展示映射版本名，查不到回退 `versionId || '待分配'`。

**验收标准（AC）**：
- [ ] Given 进入看板, when 默认加载, then 展示全部需求四泳道。
- [ ] Given 版本/优先级筛选组合, when 选择, then 展示交集结果且看板/列表同步。
- [ ] Given 有需求卡, when 点击, then 进入对应流程树。

#### 列表视图

**功能描述**：按状态分组的需求列表。

**用户故事**：作为 User，我希望切换列表视图，以便按状态集中查看。

**交互流程**：公共表头渲染一次（标题/类别/优先级/版本/状态/负责人）→ 按状态分组（各成一块，状态色标题 + 「n 项」）→ 组间虚线分割，空状态组隐藏。

**验收标准（AC）**：
- [ ] Given 列表视图, when 加载, then 公共表头一次 + 按状态分组。
- [ ] Given 某状态无需求, when 渲染, then 隐藏该空组。

#### 需求管理（新建/编辑/删除）

**功能描述**：顶栏「＋新建需求」按钮。新建/编辑弹窗（模态）字段：标题（必填）、描述（Markdown）、类别、版本、优先级、状态、负责人。

**用户故事**：作为 User，我希望新建/编辑需求，以便维护需求信息与归属。

**交互流程**：
1. 新建：填写字段 → 保存 → 留在看板刷新列表。
2. 编辑：卡片/列表行 hover「✎ 编辑」/「🗑 删除」（stopPropagation 不拦截点击）+ 详情页标题区「编辑」按钮 → 保存后看板/列表即时刷新。
3. 删除：二次确认「删除后不可恢复…」→ 移除并刷新，**不删** reqId/ 磁盘目录。

**业务规则**：新建 id = `req-` + 递增序号补零；owner 提示规则（架构→Architect；纯后端→RD；纯前端→FE）。

**关键状态**：标题空 → 保存禁用+红框；无描述 → 「暂无描述」灰色占位；描述 >4 行 → 折叠（默认 150px）+ 展开/收起。

**验收标准（AC）**：
- [ ] Given 新建弹窗标题为空, when 点保存, then 禁用并红框提示。
- [ ] Given 编辑需求改字段, when 保存, then 追加变更历史（自然语句）。
- [ ] Given 删除需求, when 确认, then 移除并保留磁盘目录。

#### 描述展示（并高级）

**用户故事**：作为 User，我希望详情页查看 Markdown 描述，以便了解需求详情。

**交互流程**：轻量 Markdown 渲染（粗体/行内代码/#~###### 标题/代码块/列表/链接/空行分段）；>4 行折叠可展开收起，切换需求重置折叠。

**验收标准（AC）**：
- [ ] Given 描述 ≤4 行, when 详情加载, then 完整显示不折叠。
- [ ] Given 描述 >4 行, when 详情加载, then 折叠并在底部显示「展开全部 ▾」。

#### 变更历史面板

**用户故事**：作为 User，我希望查看需求字段变更历史，以便审计追踪。

**交互流程**：详情页可折叠面板，时间倒序；自然语句 `谁将「字段」从「旧值」变更为「新值」`；描述不做逐字 diff（显示 填写/清空/修改了需求说明）；无历史显示「暂无变更记录」。

**验收标准（AC）**：
- [ ] Given 需求有字段变更, when 查看历史, then 按时间倒序展示自然语句变更。
- [ ] Given 需求无变更, when 查看, then 显示「暂无变更记录」。

#### 版本管理

**功能描述**：顶栏版本筛选旁「版本管理」按钮 → 模态弹窗，每个版本一行：版本名 + 状态徽标 + 需求数 + 进度汇总（待启动/进行中/已完成/已取消 计数 + 四色进度条）+ 行尾操作（推进/废弃/改名/删除）。

**用户故事**：作为 User，我希望管理版本状态，以便推进迭代。

**交互流程**：新建版本（待启动，即时同步）→ 改名（自由文本，同步顶栏与卡片）→ 推进（单向）→ 废弃（二次确认，联动需求已取消）→ 删除（有引用禁止）。

**业务规则**：
- 版本状态机：待启动 → 进行中 → 已发布单向；任意阶段可直接废弃 = 终态，v1 不可恢复。
- 废弃联动其下需求全部 status → 已取消（不写 history）。
- 发布软约束：有未完成需求时仅提示不阻止（bugfix 场景）。
- 删除有引用禁止（blocked + refCount）。
- v-backlog 待分配池锁定：仅显示，无任何操作。

**验收标准（AC）**：
- [ ] Given 版本待启动, when 推进, then 变进行中；再推进变已发布。
- [ ] Given 废弃版本, when 确认, then 版本已废弃且其下需求全部已取消。
- [ ] Given 删除有需求引用的版本, when 操作, then 禁止并提示引用数。
- [ ] Given v-backlog, when 操作, then 无任何操作可用。
