# 《评审通知复现需求》产品设计文档（PRD）

> 联调样例文档（BUG-015 数据修复入库，2026-09-10）。

## 1. 问题陈述

通知投影的联调缺少端到端样例数据，问题定位需要在真实推进过程中观察收件箱行为。

## 2. 目标

构造一条可重复推进/回退的样例需求，使七类通知在联调环境可控复现。

## 3. 功能要点

1. 需求对齐节点：pm 产出对齐文档并提评。
2. 产品设计节点：登记设计文档，提评后三位评审逐位表态。
3. RD 技术设计与评审：完整走一遍 agree → 拍板链路。
4. 缺陷环节：评审提 issue → resolve(fix) → confirm 闭环，观察 retest 子型通知。
5. 冲突环节：手动 escalate → adjudicate，观察 escalation 投影。

## 4. 非功能

- 样例数据可重复构造：同剧本重跑产生同构数据（时间戳除外）。
