## 第一部分：单条缺陷报告示例

### 示例缺陷 A（一般/P1，已修复）

| 字段 | 值 |
|---|---|
| 缺陷编号 | BUG-SETTLE-007 |
| 标题 | 结算页连续快速点击"数量+"时金额与勾选不同步 |
| 发现人 | 赵测试 |
| 发现日期/时间 | 2025-07-02 15:30 |
| 所属项目/版本 | 订单中心 v3.2 |
| 所属模块/功能 | 结算模块 / 金额计算 |
| 指派负责人 | 后端-张后端 |
| 相关需求/用例 | PRD《购物车改版》§5.2 / cart-summary-竞态 |

**严重程度/优先级**：一般（S2）/ P1

**缺陷描述**：在结算页连续快速点击"数量+"按钮（每次间隔 < 100ms）时，界面显示金额与勾选商品的实际金额不同步，偶发出现金额为上一次请求的值。

**复现步骤**：
1. 进入结算页，勾选商品 A（单价 ¥100）；
2. 快速连续点击"数量+" 5 次（间隔 <100ms）；
3. 观察底部合计金额。

**预期结果**：合计金额最终等于 ¥500（最后一次数量 5 × 单价 100）。

**实际结果**：合计金额停留在上一次的 ¥400，与数量 5 不同步（乱序响应）。

**环境信息**：
| 项 | 值 |
|---|---|
| 环境 | 测试环境（test-staging） |
| 操作系统/浏览器 | iOS 17 / Chrome 120 |
| 数据/前置条件 | 登录态会员用户，商品 A 正常 |

**附件**：[复现录屏]；[接口抓包：最后一次响应为数量4时的结果]

**处理与跟踪**：
| 字段 | 值 |
|---|---|
| 缺陷状态 | 已关闭 |
| 原因分类 | 程序错误（未做竞态/请求序号） |
| 修复方案 | 前端对金额接口加请求序号，仅应用最后一次入参对应的响应 |
| 复测结果 | 通过（普通点击与快速点击均正确，回归 3 次） |
| 关闭人/日期 | 赵测试 / 2025-07-05 |

## 第二部分：缺陷管理流程与规范（本项目实际执行）

### 1. 缺陷生命周期（本项目流转）

实际流转 10 个缺陷：
- 6 个走 新建 → 已确认 → 处理中 → 已修复 → 待复测 → 已关闭；
- 2 个复测首次未通过 → 回到处理中二次修复后关闭；
- 1 个为重复缺陷（关联到 BUG-007 后关闭）；
- 1 个（BUG-009）挂起并留决策依据。

> 全程遵循"不经复测不得关闭、拒/挂/不修复留依据"。

### 2. 缺陷等级口径（本项目采用）

| 等级 | 影响判定 | 本次遇到 | 处置时效 |
|---|---|---|---|
| 严重 S1/P0 | 核心功能不可用、数据/资金/安全高危 | 0 个 | 立即修复，阻塞发布 |
| 一般 S2/P1 | 主要功能受影响、有规避 | 2 个 | 当期修复；BUG-009 因难得复现结合依据挂起下版 |
| 轻微 S3/P2 | 轻微影响/易用性 | 5 个 | 当期修复 |
| 建议 S4/P3 | 优化建议 | 3 个 | 择期 |

### 3. 缺陷评审与处理规则（执行要点）

- 新缺陷由测试确认有效后指派后端/前端；
- 唯一 P0 未出现；BUG-007 影响金额，当日同步产品与后端并优先排期修复；
- 需求变更（如满减规则调整）走了需求变更单，未混入缺陷；
- 每个缺陷的处理意见、责任人、时间均留痕。

### 4. 缺陷周报 / 汇总（截至 2025-07-11）

| 统计项 | 数量 | 环比/趋势说明 |
|---|---|---|
| 本期新增缺陷 | 10 | 第一轮集中 9 个，第三轮 0，收敛明显 |
