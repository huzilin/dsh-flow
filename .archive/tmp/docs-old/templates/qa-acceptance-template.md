## 3. 测试资产（测试数据构造 + 测试代码）【必填】

> 说明：本节是**必填**的。验收报告除给出"测了什么、结果如何"外，还必须回答"**怎么重测**"——把本次用到的测试数据构造方法与测试代码沉淀为可复用资产，之后任何一轮回归 / 复测 / 下版迭代都直接复用本节内容重跑，**不需要重新编写测试数据与测试脚本**。
>
> 三原则：**① 数据可一键重建**（构造脚本入库、幂等可重复执行）；**② 脚本可一键复跑**（给出运行命令，无需人工翻译）；**③ 结果可对比**（复测输出与验收时基线比对）。

### 3.3 快速复测指引（给"下次重测"的操作卡）

> 说明：把复测动作压缩成 3~5 步，明确"先做什么、再做什么、以什么为通过标准"，让未参与本次验收的测试人员也能照做。**目标：按此指引可在 30 分钟内完成一轮回归重测。**

```
1. 重置数据：bash qa/data/reset.sh            # 重建 3.1 全部测试数据（幂等）
2. 运行回归：pytest qa/code/ -q               # 跑 3.2 全部自动化脚本
3. 缺口补测：对 3.2 未覆盖用例按 §2 范围手工补测（清单见 3.2 输出/判定）
4. 比对基线：与本节"验收时基线值"比对（见 §4 用例执行统计 / §6 按模块验收结果）
5. 判过标准：无新增失败 + 无 P0/P1 缺陷 → 通过；有差异 → 对照 §5 缺陷统计与 qa/defect.md 判断是否回归问题
```

## 附：测试验收文档要点

- **结论先行**：报告顶部就给出能否验收，避免只看尾部；
- **用数据说话**：执行/通过率/缺陷数/趋势，附重点缺陷；
- **对应 PRD 的 AC**：验收结果要与需求验收标准对应，形成"PRD → 用例 → 验收"闭环；
- **遗留问题要"够明确"**：写明不阻塞上线的依据，否则会进验收拉扯。
