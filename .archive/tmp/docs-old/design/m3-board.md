# M3 PRD：版本看板 + 需求池（工作台入口）

> 里程碑：M3
> 状态：**v1.1（已实现，实现回写见 `docs/design/m3-board-tech.md`）**
> 依赖：M2 流程树（点需求进入）；可视化参考 `docs/prototype/m3-board-prototype.html`

---

## 1. 目标

在「项目」tab 增加**外层入口**：进入即看到**全部需求看板**，顶部可**筛选版本与优先级**，需求以**看板 / 列表**两种格式展示；点击需求 → 进入内层流程树（M2）。

本里程碑**不包含**：创建版本/需求入口（后置）、项目切换（后置）、真实子 agent（M7）。

---

## 2. 数据模型（新增，mock）

```
.workbench/
  versions.json     # 版本列表 [ {id, name, isBacklog} ]
  requirements.json # 需求（已有，加 versionId + priority）
```

- 版本：`v1.0`、`v1.1`、`待分配`（isBacklog=true）；版本 id 用短码 `v-1`/`v-11`/`v-backlog`。
- 需求状态：`待启动 / 进行中 / 已完成 / 已取消`（复用现有 status 字段）。
- **需求优先级：`P0 / P1 / P2 / P3` 四档**（User 确认）。

---

## 3. 页面与交互

### 3.1 顶部条
- 左侧：标题「项目」+ 当前 workspace 徽标；
- 右侧：
  - **版本筛选 `<select>`**：全部 / v1.0 / v1.1 / 待分配；
  - **优先级筛选 `<select>`**：全部 / P0 / P1 / P2 / P3（与版本筛选**组合交集**）；
  - **「看板 / 列表」切换**按钮。

### 3.2 看板视图（默认）
- **列 = 状态**：待启动 | 进行中 | 已完成 | 已取消（四泳道）；
- 需求卡按 `status` 归入对应列；
- 需求卡：标题 + 类别徽标 + **优先级徽标（P0 红/P1 橙/P2 蓝/P3 灰）** + 版本 + 负责人；
- 筛选后只显示满足条件的需求。

### 3.3 列表视图
- **公共表头一次**（标题 / 类别 / 优先级 / 版本 / 状态 / 负责人）；
- **按状态分组**：待启动/进行中/已完成/已取消各成一块（状态色标题 + 项数），组间**虚线分割**，空状态组不显示；
- 同一筛选（版本 × 优先级交集）。

### 3.4 进入流程树
- 点击需求卡（或列表行）→ 切换到内层：该需求的流程树（M2）；
- 流程树顶部加「← 返回看板」回外层；
- 无流程数据的需求显示「暂无流程数据」提示 + 返回按钮。

---

## 4. 已确认决策

1. 方案 B：顶部 select 版本筛选 + 状态泳道看板 + 看板/列表切换（**非** 列=版本的飞书列式）。
2. 版本筛选用 `<select>` 下拉，不用 pills。
3. 看板列 = 状态（待启动/进行中/已完成/已取消）。
4. 数据先 mock（不建创建入口）。
5. 进入「项目」tab 默认看全部需求（版本「全部」）。
6. **优先级四档 P0/P1/P2/P3**（User 选定），属性 + 筛选 + 卡/行/详情三处展示。
7. **列表视图按状态分组**：公共表头一次 + 组间虚线分割 + 空组隐藏（User 指定）。
