## 1. 目标与范围

### 1.1 定位

「项目」tab（`conversation.view`，id=`workbench`）是工作台**外层入口**：进入即展示**全部需求看板**，顶部支持版本×优先级筛选与看板/列表切换；点击需求进入内层流程树（模块 II，见 `03-module-flow-tree.md`），形成「外层（看板/列表）⇄ 内层（流程树）」两级结构。

### 1.2 范围内

- **版本看板**：状态四泳道 + 需求卡（优先级徽标）；
- **需求池**：看板 / 列表双视图、版本×优先级筛选（组合取交集）；
- **需求管理**：新建 / 编辑（带审计）/ 删除（二次确认）+ 描述 Markdown + 需求信息 / 变更历史面板；
- **版本管理**：版本 CRUD + 单向推进 + 任意废弃 + 进度汇总。

### 1.3 范围外（后置，见 09 遗留清单）

- 多项目切换 UI（决策 6：项目=DSH workspace，数据已按项目分桶，仅缺界面）；
- 看板拖拽换列（改 `status` 仅经编辑弹窗）；
- 真实流程生成（新建需求无流程树，流程模板写死，见 `06`）。

## 2. 界面与交互（需求）

### 2.1 看板视图（默认）

- 进入 tab 默认**看全部需求**（版本「全部」× 优先级「全部」）；顶部提供「看板 / 列表」切换按钮；
- **列 = 状态四泳道**：待启动 | 进行中 | 已完成 | 已取消；列头 = 状态色圆点 + 状态名 + 该列条数，空列显示空容器；
- **需求卡要素**：标题 + 类别徽标 + 优先级徽标 + 版本名 + 负责人；
- **优先级徽标颜色**：P0 红 / P1 橙 / P2 蓝 / P3 灰；
- **筛选**：版本下拉（全部/各版本/待分配）× 优先级下拉（全部/P0~P3），两维度**取交集**，看板与列表共用同一过滤结果；「全部」为前端虚拟选项（`__all__`）不入库；
- 卡片点击 → 进入流程树（§2.5）。

### 2.2 列表视图

- **公共表头渲染一次**：标题 / 类别 / 优先级 / 版本 / 状态 / 负责人；
- **按状态分组**：待启动 / 进行中 / 已完成 / 已取消各成一块（状态色标题 + 「n 项」），组间用**虚线分割**，**空状态组隐藏**；
- 与看板共用同一筛选结果及版本名 / 优先级色映射；行点击 → 进入流程树。

### 2.3 需求管理

顶栏（看板/列表共用）「＋ 新建需求」按钮。

**新建 / 编辑弹窗（模态）**——字段与必填：

| 字段 | 控件 | 必填 / 默认 |
|---|---|---|
| 标题 | 文本输入 | **必填**（空则保存禁用 + 红框） |
| 描述 | 多行 textarea（支持 Markdown，含代码块/链接） | 可空，默认 `''` |
| 类别 | 下拉：需求任务 / 任务 / 版本规划任务 | 默认 需求任务 |
| 版本 | 下拉：各版本 / 待分配 | 默认 待分配（v-backlog） |
| 优先级 | 下拉：P0/P1/P2/P3 | 默认 P2 |
| 状态 | 下拉：待启动 / 进行中 / 已完成 / 已取消 | 默认 待启动 |
| 负责人 | 文本输入 + 角色 datalist 建议 | 默认 Leader |

- 新建 id = `req-` + 递增序号补零（如 `req-007`）；新建保存后**留在看板刷新列表**；
- **编辑入口**：卡片/列表行 hover 出现「✎ 编辑」「🗑 删除」（`stopPropagation` 不拦截点击进详情）+ 详情页标题区「编辑」按钮；保存后看板/列表即时刷新（编辑态且在详情页则重拉快照）；
- **删除二次确认**：「删除后不可恢复，确定删除需求「xxx」？」；确认后从列表移除并刷新，**不删** `reqId/` 磁盘目录；删除的是当前详情需求则自动返回看板；
- owner 填写规则（提示、不做强校验）：架构需求→Architect；纯后端→RD；纯前端→FE；审批/讨论/简单 task→直接指定。

**需求信息面板**（详情页，key-value 网格）：负责人 / 版本 / 优先级（彩色徽标）/ 状态（彩色徽标）/ 类别 / 创建时间 / 更新时间；缺字段显示 `—`。

**需求描述卡片**（详情页）：

- 轻量 **Markdown 渲染**：粗体 / 行内代码 / `#`~`######` 标题 / 代码块 / 列表 / 链接 / 空行分段；未填写显示「暂无描述」（灰色占位）；
- **超长折叠**：≤ 4 行完整显示不折叠；> 4 行折叠（默认高度 150px，`overflow:hidden`），底部「展开全部 ▾ / 收起 ▴」，切换需求时重置为折叠；
- 看板卡片 / 列表行**不**展示描述（保持简洁，进详情看）。

**变更历史面板**（详情页，可折叠，时间倒序）：自然语句 `谁将「字段」从「旧值」变更为「新值」`（如 `User 将「版本」从「v1.0」变更为「v1.1」`）；版本映射为版本名；描述字段不做逐字 diff，显示`谁填写/清空/修改了需求说明`；无历史显示「暂无变更记录」。

### 2.4 版本管理

- 入口：顶栏版本筛选旁「版本管理」按钮 → 模态弹窗（可叠加任意视图），每个版本一行：
  - 版本名 + 状态徽标 + 需求数；
  - **进度汇总**：`待启动 n · 进行中 n · 已完成 n · 已取消 n` 计数 + 四色分段**进度条**（段宽按占比）；
  - 行尾操作：`▶ 推进`（待启动/进行中显示）· `✖ 废弃`（非废弃态显示）· `✎ 改名` · `🗑 删除`；
- **新建版本**：弹窗顶部输入框 + 按钮 → `state=待启动`，立即同步出现于列表与顶栏筛选下拉；
- **改名**：行内输入（自由文本）→ 保存后顶栏筛选与需求卡片同步更新；
- **删除**：**有需求引用时禁止**（提示「该版本下还有 n 条需求，请先移出」）；无引用直接删除；
- **废弃**：弹**二次确认**「废弃后版本下 n 条需求将全部转为已取消，且 v1 不支持恢复，确定？」→ 确认后版本置已废弃、其下需求全部 `status → 已取消`，看板/列表同步刷新并提示被取消数；
- **发布软约束**：推进到「已发布」时若版本下仍有未完成需求（待启动/进行中），**仅提示不阻止**（bugfix 场景），提示未完成需求数；
- **v-backlog 待分配池锁定**：仅显示，无任何操作（不可删/不可改名/无状态推进）；
- 已废弃版本行灰显 + 「已废弃 · v1 不可恢复」提示；
- 需求归入版本：沿用编辑表单的版本下拉，**不加快捷入口**（推进/废弃主要靠 agent 工具，见 `07`）。

### 2.5 进入流程树

- 点击需求卡 / 列表行 → 内层流程树（模块 II，`03-module-flow-tree.md`）；顶部「← 返回看板」回外层；
- 无流程数据（无 `flow.json`）的需求：显示**「暂无流程数据」**+ 返回按钮，**不卡加载中**；需求信息面板照常渲染（无流程也能看需求属性）。

## 3. 数据与规则（设计）

### 3.1 数据结构

载体文件 `requirements.json`、`versions.json`（项目级全局，每 workspace 一套）；实体字段定义以 `05-domain-model.md` §2.1/§2.2 为准，本文不重写。本模块特有约定：

- **优先级颜色映射**（纯展示约定）：P0 红 / P1 橙 / P2 蓝 / P3 灰；缺省渲染 `—`；
- **版本名自由文本**：`id` 为稳定短码（`v-<n>`、`v-backlog`），`name` 为自由展示名（`v1.0`、`2.0 迭代`…）；展示时 `versionId → versions.json.name` 映射，查不到回退 `versionId || '待分配'`；
- **版本删除引用检查**：`deleteVersion` 前置扫描 `requirements.json`，存在 `versionId` 指向该版本则拒绝（返回 blocked + 引用数）；「全部」筛选为前端虚拟选项（`__all__`）不入库。

### 3.2 编辑审计（history[]）

- **7 字段 diff**：`title / description / category / versionId / priority / status / owner`；变化判定 `args[f] !== undefined && String(args[f]) !== String(req[f] || '')`；`from`/`to` 存**原始值**（`versionId` 存短码，展示时映射版本名）；
- 有变化才追加 `{ at, by:'User', changes:[{field, from, to}] }`；**无变化不追加**（避免空审计），`updatedAt` 始终刷新；
- 新建需求 `history=[]`；**删除不写审计**（整条移除）、**不删** `reqId/` 目录；
- 审计计算在 **Host** 完成（防 Client 伪造）；`by` 固定 `'User'`（无登录体系）；
- 展示：时间倒序、自然语句，空值显示「（空）」；描述字段不做逐字 diff，按 from/to 是否为空显示「填写 / 清空 / 修改了需求说明」。

### 3.3 版本状态机（精确转移表）

状态常量 `S = ['待启动', '进行中', '已发布', '已废弃']`；`v-backlog` 的 `state` 恒为 `待启动` 且不参与任何转移。

| 动作 | 前置 | 下一态 | 副作用 / 拒绝 |
|---|---|---|---|
| advance | 待启动 | 进行中 | 开始该版本迭代 |
| advance | 进行中 | 已发布 | 版本交付；若其下仍有未完成需求（待启动/进行中）返回 `unfinished: n`，**仅提示不阻止** |
| advance | 已发布 / 已废弃 | — | 拒绝 `{ok:false, error}`（已发布无推进目标；已废弃为终态） |
| advance | v-backlog | — | 拒绝：待分配池无状态操作 |
| deprecate | 任意非废弃态 | 已废弃 | **终态，v1 不可恢复**；联动其下所有需求 `status → 已取消`（`updatedAt` 刷新、**不写** history——联动非人工编辑）；操作前需二次确认 |
| deprecate | 已废弃 | — | 拒绝（幂等）`{ok:false, error:'already deprecated'}` |

> 废弃**双写顺序**：先写 `versions.json`（state=已废弃），再写 `requirements.json`（需求取消）；任一失败返回 error（此阶段不引入事务，人工可调）。

## 4. Host 接口

全部 `wb.*` RPC 经 `harness.handle` 注册；**写文件显式传 `writePolicy()`（workspaceRoot=PROJECT）**，返回**纯 JSON（lossless，无 `undefined` 字段，缺值归一 `null`/`[]`）**（决策 10）；写操作返回最新快照驱动重渲染，无轮询。

**列表（3）**

| 方法 | 入参 | 出参 / 副作用 |
|---|---|---|
| `wb.listRequirements` | — | 返回 `requirements.json` 全量数组（非数组归一 `[]`） |
| `wb.listVersions` | — | 返回 `versions.json` 全量数组（含 state） |
| `wb.getRequirement` | `{ reqId }` | 聚合快照 `{requirement, flow, artifacts, comments}`；**flow 缺失返回 `null`** |

**需求写（3）**

| 方法 | 入参 | 出参 / 副作用 |
|---|---|---|
| `wb.createRequirement` | `{ title, description?, category?, versionId?, priority?, status?, owner? }` | title 必填；id 自动递增补零；默认 需求任务 / v-backlog / P2 / 待启动 / Leader；`history=[]` → `{ok, reqList}` |
| `wb.updateRequirement` | `{ reqId, ...可改字段 }` | Host 计算 7 字段 diff → 有变化追加 history → 刷新 updatedAt → `{ok, reqList}` |
| `wb.deleteRequirement` | `{ reqId }` | 移除列表项（不删 `reqId/` 目录）→ `{ok, reqList}` |

**版本写（5）**

| 方法 | 入参 | 出参 / 副作用 |
|---|---|---|
| `wb.createVersion` | `{ name }` | name trim 后非空必填；id 递增；state=待启动、isBacklog=false → `{ok, verList}` |
| `wb.updateVersion` | `{ versionId, name }` | 改名（自由文本；`v-backlog` 拒绝）→ `{ok, verList}` |
| `wb.advanceVersion` | `{ versionId }` | 按 §3.3 转移；发布且下有未完成需求返回 `unfinished: n`（提示不阻止）→ `{ok, verList}` |
| `wb.deprecateVersion` | `{ versionId }` | 版本置已废弃 + 其下需求 status→已取消（双写两文件）→ `{ok, verList, reqList, depCount}` |
| `wb.deleteVersion` | `{ versionId }` | 有需求引用 → `{ok:false, blocked:true, refCount:n}`；无引用删除 → `{ok, verList}` |

> agent 侧 `wb_*` 模型工具与 UI 复用同一套领域逻辑（同一审计 / 状态机），工具清单见 `07-tools-and-orchestration.md`。

## 5. 定稿要点

1. 方案 B：顶部 `<select>` 版本筛选 + **状态泳道**看板 + 看板/列表切换（非列=版本）。
2. 优先级 **P0/P1/P2/P3 四档**（P0 红 / P1 橙 / P2 蓝 / P3 灰），属性 + 筛选 + 卡/行/详情三处展示。
3. 版本 × 优先级筛选**组合取交集**，看板与列表共用同源过滤结果。
4. 列表**按状态分组**：公共表头一次、组间虚线分割、**空组隐藏**。
5. 编辑**带审计**：Host 计算 7 字段 diff 写 `history[]`，无变化不追加；`by` 固定 `'User'`。
6. 描述支持 **Markdown 渲染**（代码块/链接），超长折叠（>4 行，默认 150px，可展开收起）。
7. **删除二次确认**（需求与版本均适用）；需求删除**不删磁盘目录**。
8. **新建需求无流程树**：流程不扩展，详情显示「暂无流程数据」+ 返回。
9. 版本状态机：**待启动 → 进行中 → 已发布单向推进**（不可回退）；**任意阶段直接废弃 = 终态，v1 不可恢复**。
10. **废弃二次确认**；废弃联动其下需求全部 `status → 已取消`（不写 history）。
11. **发布软约束**：有未完成需求时仅提示不阻止（bugfix 场景）。
12. **删除有引用禁止**（blocked）；版本名自由文本；`v-backlog` 待分配池锁定（不可删 / 不可改名 / 无状态操作）。
