reviewState 是每一个评审位（agent）各自的轮转（1/10），不是节点整体状态；节点级聚合由 collect 内置完成（不暴露、无专门 state）。

per-agent 三态（每个评审位独立轮转）

reviewing
评审+表态进行中
出口：agent 自判上报
agree
达成一致（已表态）
agent 自己没有 open 工单
unagree
未达成一致（已表态）
agent 自己知道有 open 工单
上报即判：plugin 不判 open 工单——agent 自己知道有工单就报 unagree，没有就报 agree

collect · 聚合收集（plugin 内置，不暴露）

①收票是否全表态完成（实时查询各 reviewer）
②判定全 agree → approved（进入下一节点）；有 unagree → 通知 owner 澄清 → 回①重新收集
③再收票澄清后 plugin 将澄清 issue 发给对应 reviewer（followup / 复用通道）→ reviewer 回 reviewing 重新表态——等待重表态阶段不设专门 state（审批内置，不挂 action 不暴露）→ 重复流程
输出approved / rejected = collect 的输出结果（approved 进下节点 / rejected 回上节点），写入 last_decision
